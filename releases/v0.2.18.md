# v0.2.18

## New Features

### Response body Save As
- The response Body tab now has a Save As button next to Copy body. It opens a save dialog with the right file-type filter for the response's media type and writes the body to the file you choose. Large responses that are only partially previewed save the captured prefix, and the button reads "Save preview" in that case.

### Open in Notepad++
- On Windows, a second button opens the response body directly in Notepad++ when it is installed in a standard location; otherwise the body opens in your default text editor.

## Fixes
- The Save As E2E test originally shipped with v0.2.17 checked the operating system running the test instead of the browser's user agent (which the app uses to decide whether to show the Open in Notepad++ button). CI's Linux runner simulates a Windows browser, so the test failed there and v0.2.17 was never released. The test now matches the app's own detection logic; no application code changed relative to that run.

## Platform Notes
- **Why there is no v0.2.17 release**: the v0.2.17 tag was removed after its CI run failed on the test-only issue described above, before any release was published. v0.2.18 is the first release containing the Save As feature.
- Save As saves the text exactly as shown in the viewer; binary/download responses keep using the dedicated download flow with its own save dialog.
- The Open in Notepad++ button appears on Windows only. macOS and Linux releases remain manual downloads; Windows in-app updates continue to use the packaged updater contract (installer + blockmap + `latest.yml`).

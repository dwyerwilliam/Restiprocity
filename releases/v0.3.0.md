# v0.3.0

The first feature release since v0.2.18.

## New Features

### OAuth 2.0 sign-in
- Authorization Code with PKCE: **Sign in** opens your default browser and returns to a loopback address on this computer (default `127.0.0.1:42813`, editable). Access tokens are refreshed when the provider issues a refresh token.
- Client Credentials requests keep working. Cancelling a send now also cancels its token request.
- Tokens are kept in memory only and are gone when the app closes. Copy as cURL includes a token only if one is already cached.
- The Password grant is not supported. A request set to it keeps its settings, but sending stops with a message that says so. (v0.2.18 sent a client-credentials token request for every OAuth grant.)

### Import and export
- Import OpenAPI 3.0 and 3.1 (JSON or YAML), Postman v2.1 collections and environments, and Insomnia v4 JSON and v5 YAML exports from the sidebar, as well as Restiprocity's own export files. An import is all or nothing: if anything fails, nothing changes.
- Export a request, a folder or the whole collection to a file. The file includes authentication credentials.
- **Copy as cURL** (right-click a request) uses the active environment and lists anything it could not carry over.
- OpenAPI imports use the editable placeholder `https://example.invalid` for relative servers, never load external references, and reject documents with more than 100,000 values or 10,000 operations. Generated samples are drafts: review them before sending.

### Multipart file uploads
- File parts are sent byte for byte, including binary and empty files. The whole encoded form is limited to 32 MiB and is held in memory while it is prepared. A missing file stops the send before any network activity.

### Environments and variables
- Environments can be nested: a child inherits its parent's variables and can override them. Create and edit them in the environment editor.
- A variable's value can refer to other variables (`{{base}}/users`). A cycle, more than 64 levels of nesting, or a result over 1 MiB stops the send with an error before anything is sent.
- The URL field grows with long URLs, and inserting a variable keeps your undo history.

### Response details
- The Timings tab shows measured DNS, TCP and TLS time for a new connection, and says so when a connection was reused.
- History entries reopen in the response viewer. The history entry of a deleted request opens as a temporary view.

## Fixes
- The save dialog for a downloaded response now belongs to the app window instead of opening unattached.

## Upgrading from v0.2.18
- Your collections, folders, environments and settings load as they are, and opening them does not rewrite those files.
- History saved by v0.2.18 and earlier stays in the list but cannot be reopened: those versions did not record the request's method and URL with each entry. Trying shows "Unable to reopen this history response: History entry has an invalid method." Entries saved from now on reopen normally.

## Platform Notes
- Cookie values are no longer stored in new history entries. Entries saved by earlier versions are not changed.
- Secret variables are masked in the editor but stored as plain text in your local data folder, and response bodies are not scrubbed for secrets.
- The Windows installer is unsigned, and in-app updates are Windows-only. macOS and Linux releases remain manual downloads.
- Building from source needs Node 26.13.0 (`.node-version`). A clean `npm ci` now installs Electron correctly under it, which it did not before this release.
- The build workflow can also be run by hand on a branch. It builds and tests on all three systems and publishes nothing.

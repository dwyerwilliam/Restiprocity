# v0.3.1

Secret variables can now be encrypted on disk.

## New Features

### Encrypted secret variables
- Environment variables have three types. **Standard** values are visible and stored as plain text. **Confidential** values are masked in the editor and previews but stored as plain text on disk. **Secret** values are masked and encrypted at rest with the operating system's secret store: DPAPI on Windows, Keychain on macOS, or a recognized keyring on Linux. No account or app password is needed.
- A masked value stays masked wherever it is used: a Standard value that refers to a Confidential or Secret one is masked in the URL preview too. Revealed values are hidden again when the window loses focus or you switch environments.
- **Copy as cURL** stops when the command contains a Secret or Confidential value, or a cached OAuth token, and copies only after you choose **Copy with secrets**.
- Without a usable secret store (for example a Linux desktop with no keyring), a Secret cannot be saved and the editor says why. Standard and Confidential values still save.
- Changing a saved Secret or Confidential value to a less protected type asks for confirmation when you save, and says what changes.
- A send that uses a Secret that cannot be decrypted fails before any network activity. Requests that don't use it are unaffected.
- Environment files are now written through a temporary file and a rename, so an interrupted save leaves the previous file in place.

## Fixes
- History entries whose URL starts with a variable reopen again. They were stored without a URL and failed with an error that Retry could never clear; the list shows "[URL not recorded]" for them.
- History saved by v0.2.18 and earlier now says "This entry was saved by an older version and can't be reopened." and offers no Reopen or Retry button, instead of a confusing "invalid method" error.
- Opening a response body in an external editor or the default app no longer uses the server's suggested file name. The file is named from the content type, and everything except JSON opens as plain text, so a response cannot choose which program opens it or have a browser run it.
- The Timings tab no longer shows connection setup as unmeasured when Chromium makes a request of its own during a send. This happened mostly on Linux with a new profile, while the spellcheck dictionary was downloading.

## Under the Hood
- The app window now runs inside Chromium's sandbox, and so would any window added later. Starting the app with `--no-sandbox` still works and turns this off.
- The app's page has a content security policy: it runs only the app's own script and makes no network requests itself. Requests you send still go through the main process, as before.
- The window refuses to navigate away from the app or open other windows.
- The app refuses camera, microphone, location, notification and device access. It never used them; Electron allows them unless told otherwise.
- The main process answers only the app's own page, and no longer accepts an item ID that could name a file outside the data folder.
- A masked value is revealed only while its environment is open in the editor.
- Packaged builds can no longer be started as a plain Node.js program or with a debugger attached to the main process, ignore `NODE_OPTIONS`, and load code only from the app's own archive. On Windows and macOS the archive is checked when the app starts. The builds are still unsigned, so this catches accidental or casual changes, not someone who can replace the whole program.

## Upgrading from v0.3.0
- Your collections, folders, environments and settings load as they are.
- Secret values saved by v0.3.0 and earlier are plain text on disk. They now appear as Confidential with an **Unencrypted** mark. Use **Encrypt as Secret** on one value, or **Encrypt N value(s) as Secret** for the whole environment. Nothing is converted until you choose to.
- Old backups, exports and copies of the data folder can still hold the plain text. Restiprocity does not erase them.
- Before installing an older version again, back up the `environments` folder in your data folder. An older build does not understand encrypted values and can overwrite them if you save that environment.

## Platform Notes
- Encrypted values are bound to this computer and OS account. Copying the data folder to another machine or account can leave Secrets unreadable; the app keeps the unreadable value rather than discarding it, and you can replace or delete it. Keep the original source for every Secret.
- Encryption protects the file at rest. Other programs running as your user can usually read a decrypted value.
- Secret values imported from Postman and Insomnia arrive as Confidential (plain text on disk) with a warning; encrypt them in the editor.
- Response bodies are not scrubbed for secrets.
- The Windows installer is unsigned, and in-app updates are Windows-only. macOS and Linux releases remain manual downloads.

# v0.2.15

## Fixes
- 4xx error responses with a missing `content-type` header (a common behavior of proxies and gateways) no longer open a file-save dialog in the Body tab. Their bodies now render inline as text, so the status code and any body text are visible immediately.
- Error responses with no body show an inline "404 Not Found — Response has no body." style message instead of download affordances. Explicitly binary-typed error bodies (e.g. `application/octet-stream`) and oversized bodies keep the download flow.

## Platform Notes
- Windows in-app updates continue to use the packaged updater contract (installer + blockmap + `latest.yml`); macOS and Linux releases remain manual downloads.
